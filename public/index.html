Panduan custom endpoint produk

Endpoint menerima POST JSON dengan action, query, dan context (account_id, session_id, customer, request_id). Token opsional dikirim sebagai Bearer token. Respons wajib HTTP 200 JSON.

Action get_products, query berisi nama atau string kosong. Respons {"products":[{"name":"Produk A","type":"product","description":"Produk harian, satuan pcs","price":125000,"stock":10,"active":true}]}. Maksimal 20 produk; harga dalam rupiah; nama wajib unik per sesi.

Endpoint wajib membatasi data menurut context dan token. Endpoint HTTPS publik, tanpa redirect; batas respons 32 KB dan timeout 15 detik. Mengganti URL tanpa token baru menghapus token lama.

            Referensi REST API

            Gunakan dari backend aplikasi, cURL, Postman, atau layanan otomasi. n8n merupakan salah satu pilihan integrasi.

            Autentikasi & mulai cepat

            Buat API key di menu Integrasi. Kirim melalui header X-API-Key pada setiap request. Satu Base URL dipakai semua akun; key menentukan kepemilikan sesi dan data. Gunakan Content-Type: application/json untuk body JSON. Simpan key pada backend aplikasi Anda.

            Base URL: . Endpoint gateway tidak memakai awalan /api, kecuali pemeriksaan identitas /api/client/me. Pengaturan dashboard dan pembelian menggunakan login browser, bukan API key.

            export BASE_URL="BASE_URL_APLIKASI"
export API_KEY="KEY_ANDA"

curl "$BASE_URL/api/client/me" -H "X-API-Key: $API_KEY"
curl "$BASE_URL/sessions" -H "X-API-Key: $API_KEY"
            Daftar endpoint

            :id adalah ID sesi, webhook, atau media sesuai rutenya. Ganti dengan ID sebenarnya.

            MetodeEndpointBody / fungsi
            GET/api/client/meIdentitas akun API key.
            GET/statsStatistik sesi akun.
            GET/sessionsDaftar sesi akun.
            POST/sessions{"id":"toko"} — membuat sesi; lanjutkan dengan QR.
            GET/sessions/:idDetail sesi, status, filter, dan status layanan.
            GET/sessions/:id/qrStatus dan qr berupa data URL PNG atau null; polling hingga connected.
            POST/sessions/:id/logoutMemutuskan perangkat WhatsApp.
            POST/sessions/:id/reconnectMemasangkan ulang sesi yang logout.
            DELETE/sessions/:idMenghapus sesi dan auth lokal.
            PUT/sessions/:id/filter{"filter":"all"} — all, private, atau group.
            POST/sessions/:id/messages/text{"to":"628123456789","text":"Halo"}
            POST/sessions/:id/messages/media{"to":"628123456789","type":"image","url":"https://example.com/foto.jpg","caption":"Halo"}
            POST/sessions/:id/typing{"to":"628123456789","state":"composing"} — composing atau paused.
            POST/sessions/:id/read{"from":"628123456789","messageId":"ID_PESAN"} — sender opsional untuk pengirim grup.

            Kirim teks & media

            Nomor pribadi memakai format internasional tanpa + atau spasi, misalnya 628123456789. Grup memakai JID, misalnya 123456789-123@g.us. Sesi harus terhubung dan aktif sesuai paket.

            curl "$BASE_URL/sessions/toko/messages/text" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: pesanan-001" \
  -d '{"to":"628123456789","text":"Pesanan Anda siap."}'

// Contoh respons sukses
{"messageId":"ID_PESAN","to":"628123456789@s.whatsapp.net","requestId":"pesanan-001"}

            Media mendukung image, document, audio, dan video. Field wajib: to, type, url. Field opsional: caption dan filename. URL harus HTTP/HTTPS publik. Media dibatasi 32 MiB per file. Sukses berarti diterima untuk dikirim, bukan bukti sudah dibaca penerima.

            Contoh JavaScript (backend)
            const response = await fetch(`${process.env.NCWA_URL}/sessions/toko/messages/text`, {
  method: "POST",
  headers: {
    "X-API-Key": process.env.NCWA_API_KEY,
    "Content-Type": "application/json",
    "Idempotency-Key": "pesanan-001"
  },
  body: JSON.stringify({ to: "628123456789", text: "Halo" })
});
const result = await response.json();
if (!response.ok) throw new Error(result.message || result.error);
console.log(result.messageId);
            Webhook, media masuk & realtime

            Daftarkan URL publik melalui POST /webhooks. Tanpa sessionId, webhook menerima event seluruh sesi milik akun. Maksimal 20 langganan per akun. Payload dikirim sebagai JSON melalui HTTP POST; penerima harus merespons sukses (2xx).

            {"event":"message","sessionId":"toko","messageId":"ID_PESAN","from":"628123456789","sender":"628123456789","isGroup":false,"groupId":null,"type":"text","text":"Halo","timestamp":1700000000,"media":null}

            Contoh di atas adalah event pesan teks; field media terisi jika media berhasil disimpan. Event koneksi memakai session.status dan session.qr. Unduh file melalui GET /media/:id dengan API key yang sama.

            Pengiriman webhook gagal dicoba hingga empat kali total. Proses penerima perlu menangani duplikasi, misalnya berdasarkan sessionId dan messageId untuk pesan. SSE memakai GET /events dengan header X-API-Key; key pada query URL tidak didukung. Event SSE tidak diputar ulang ketika tersambung kembali. Maksimal lima koneksi SSE per akun.

            curl -N "$BASE_URL/events" -H "X-API-Key: $API_KEY"
            Idempotensi, kredit & penanganan error

            Kirim Idempotency-Key yang tetap untuk satu operasi bisnis (1–128 huruf, angka, underscore, atau tanda hubung). Retry dengan payload sama tidak mengirim ulang pesan yang sudah tercatat. Payload berbeda dengan key sama ditolak. Satu teks atau media beserta caption memakai satu kredit; gagal pasti melepas reservasi. Hasil tidak pasti menahan reservasi: jangan membuat key baru untuk langsung mengirim ulang.

            HTTPPenanganan
            400Periksa body, nomor, URL, dan Idempotency-Key.
            401 / 403Periksa kredensial dan hak akses akun.
            404Pastikan ID milik akun dan resource masih tersedia.
            409Periksa error: insufficient_credits, session_limit, idempotency_conflict, atau request_*.
            429 / 503Batas koneksi atau antrean tercapai; beri jeda sebelum mencoba lagi.
            502Bedakan send_failed dan send_unknown; jangan otomatis kirim ulang hasil tidak pasti.
            {"error":"insufficient_credits","message":"Kredit habis."}

            Field message dapat tidak tersedia. Gunakan error untuk penanganan programatik. Maksimal 32 permintaan pengiriman aktif per akun.
